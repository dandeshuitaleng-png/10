# 趣味闯关｜视觉美术与UI质量评判标准

版本：v1.0　日期：2026-10-07  
适用项目：`/Users/huangnianpeng/Desktop/yx/demo`  
用途：风格选定、资产审阅、界面评审、阶段验收、外部AI交接。  
状态：项目评判标准提案，含当前版本单人初评；尚未经过用户审美确认、目标玩家测试或真机验收。

## 1. 评判目标与不可变边界

目标不是“像AI生成的漂亮海报”，而是让10—16岁玩家愿意进入，能理解自己在哪一关、该点哪里、为什么失败，以及接下来能做什么。美术应使玩家记住这个乡村知识游戏，UI应支持读题和操作。

| 项目 | 本项目固定要求 |
| --- | --- |
| 玩家 | 10—16岁；避免幼儿化，也避免把界面做成成人数据后台 |
| 内容 | 十步芳草、千年文脉、金色产业、青山绿水；分别对应红色故事、乡土文脉、产业物产、生态风光 |
| 游戏结构 | 四主题、每主题四关、每关随机十题、四选一、全部答对通关 |
| 玩法呈现 | 阶梯解锁；通关积分10/15/20/30；单主题证书与16关总证书 |
| 失败呈现 | 首次答错可分享复活一次，恢复原题；复活后再错仅当前关卡当日锁定 |
| 视觉方向 | 湖蓝＋暖橙；平面2D；清楚的形状、受控的纹理、可信的乡村内容 |
| 排除方向 | 塑料或黏土3D、写实商品渲染、镜面高光、金色立体字、果冻按钮、低龄大眼角色、满屏发光 |
| 设计边界 | 不因美术创作新增Boss、额外节点、星级、拖拽题、收集货币或其他玩法 |
| 原图角色 | 用户提供的效果图只作参考，不能凌驾于文字需求 |

“不AI”不作为单一评分项，不凭猜测判断图片是否由AI生成。判断其可见后果：结构是否合理、元素是否服务内容、细节是否可控、系列是否一致、是否有专属设计。AI来源本身不扣分，人工来源也不自动加分。

## 2. 评判结果如何产生

### 2.1 三道独立门槛

1. **需求与安全门槛**：是否表达了正确规则，能否读、能否点，有无关键遮挡。
2. **视觉质量评分**：按第4节100分表评审；每一分必须能关联到画面或检查记录。
3. **人和设备验收**：项目负责人确认审美方向；目标玩家理解与操作检查；微信Android/iOS实机检查。

三者分别记录。高分不能覆盖玩法错误，自动测试不能代替审美认可，浏览器截图不能代替微信真机。

### 2.2 评分方法

本表20项，每项满分5分，总分100分。项目设定的字号、间距、时长和通过线均为**拟采用的项目验收标准**，不是微信官方规定或普遍科学定律。外部标准参考单独注明。

| 分值 | 统一解释 |
| --- | --- |
| 0 | 有证据表明缺失、错误或无法使用；不要用0代替“还没检查” |
| 1 | 明显不符合方向，或存在多处严重缺陷，需要重做 |
| 2 | 可辨识、基本能用，但有明确且反复出现的问题，需要较大修改 |
| 3 | 达到基本可用水平，有局部明显缺点，尚未达到正式美术质量 |
| 4 | 满足该项指标与所需证据，仅有不影响判断的小缺点 |
| 5 | 满足4分条件，并在专属性、完成度或实测表现上有明确额外优势；写出优势证据 |
| 待测 | 没有足够证据；留空并列出待补证据，不算通过，不自动折算成满分 |

单项不适用必须给出理由，由项目负责人确认；不能用“不适用”排除尚未完成的正式页面。证据不完整时报告“已评项目得分/已评项目满分”，不得归一化冒充完整100分结果。

### 2.3 拟定通过线

| 总分 | 判定 |
| --- | --- |
| 90—100 | 有条件作为正式视觉基准；仍须三道门槛全部通过 |
| 85—89 | 候选稿；清掉缺陷并完成复核后再验收 |
| 75—84 | 方向基本成立，继续修改，不能声称美术验收通过 |
| 60—74 | 有明显短板，先补方向或系统性问题 |
| 低于60 | 当前设计不足以作为正式基准，需要重点重构 |

正式验收另外要求：A美术定位至少16/20，B资产至少16/20，C排版至少12/15，D色彩至少12/15，E/F各至少8/10，G/H各至少4/5；任何单项低于3分不得通过。阶段样板可先评已交付范围，但不能据此声称全部游戏美术完成。

## 3. 不可用总分抵消的阻断项

下列任一项失败，必须先修复；缺证据则标“待测”，不能标“通过”。

| 编号 | 阻断问题 | 检查与判断 |
| --- | --- | --- |
| G01 | 题干、四选项、确认按钮或关键规则不可见 | 每个目标屏幕和长内容样例完整检查；不能依赖缩小关键文字解决 |
| G02 | 按钮落入胶囊、系统手势或刘海危险区域 | 以实际平台安全区和胶囊坐标检查；项目要求至少预留44px顶部区域 |
| G03 | 可操作区域互相覆盖或装饰挡住控件 | 显示触摸区域并实点；弹窗出现时不能操作背后选项 |
| G04 | 必须读取的普通文字对比度不足4.5:1 | 检查每种实际前景/背景组合，图片上文字要检查最差区域；项目统一采用4.5:1文字门槛 |
| G05 | 正式页面显示与需求不同的关卡、复活或锁定规则 | 对照四主题/16关/十题/一次复活/仅当前关卡锁定；不是全主题或全游戏锁定 |
| G06 | 未发生的分享、积分、证书或解锁被显示为正式成功 | 区分设计状态、试玩数据和正式记录；页面和交付说明都应清楚 |
| G07 | 核心建筑、人物、器物有明显错构、拼接或历史表达错误 | 100%查看关键对象，并由内容负责人核实具体地点/人物；通用示意不得冒充真实遗址 |
| G08 | 缺中文、乱码、透明边、拉伸或严重模糊 | 实际渲染检查，不只看设计源图 |
| G09 | 触碰主色/风格禁区且未获得用户改变方向的指令 | 不能以“更高级”为理由改成塑料3D或整屏高饱和原色 |
| G10 | 上线验收缺少关键实机或来源证据 | iOS/Android操作录像、屏幕参数、资源来源与使用依据应可追溯；该项针对正式交付 |

G04的4.5:1参考WCAG普通文字标准，本项目主动将其用于所有关键文字，避免因字号折算而放宽要求。WCAG对部分大字和非活动控件有不同规则；这里不声称小游戏已通过完整WCAG认证。

## 5. 可直接用于制作的UI指标

以下数值以375逻辑宽作为设计基准；导出750图时翻倍只是图像像素变化。逻辑单位、CSS px、设备点和物理像素不能混为一谈。当前工程会按屏幕宽度缩放，所以44逻辑单位在320宽屏上只有约37.5实际显示px；触控验收必须看缩放后的区域，而不是只读源码数值。

### 5.1 字体与布局

| 对象 | 拟定制作指标 | 验收注意 |
| --- | --- | --- |
| 游戏标题 | 30—34，粗体；可有专属字形，但必须可读 | 不是每个页面都放一个巨大标题；不采用厚金边 |
| 页面标题 | 24—30，600—700 | 同层级同字重；不能压缩玩法内容 |
| 题干 | 22—24，600；默认不超过3行的常规版式 | 真题更长时启用已设计的扩展布局，不能直接截断或无限缩字 |
| 四选项 | 16—18，400—600；允许两行 | 若两行，选项高度随内容增加；不能所有题固定49高单行 |
| 进度/说明 | 14—16；地图关卡条件至少14 | 次要标签也应有可读性，避免当前11px地图条件 |
| 行距 | 中文正文建议字号的1.4—1.6倍 | 用真实题目检查，不将比例等同于必然好看 |
| 页面边距 | 常规16—24；同一页面对齐基线一致 | 场景可适度出血，文本仍服从共同边距 |
| 纵向节奏 | 以4为基础，常用8/12/16/24/32 | 光学调整可例外，说明原因；不能机械网格化 |
| 卡片/弹窗 | 圆角16；按钮/选项12 | 允许圆形关卡节点；圆角统一不代表形状全部一样 |
| 控件描边 | 常规1—1.5逻辑单位，选中可更明确 | 细描边实际设备检查；不靠微弱边框承载唯一状态 |
| 主要按钮 | 通常48—52逻辑高；必须满足实际触控目标 | 一页一个主要行动；非必须的次级行动降权 |

| 细描边#A7BBB8 / 内容白#FFFEF9 | 1.99:1 | 未达到拟定3:1必要边界标准，需增强或增加其他有效标识 |
| 细描边#A7BBB8 / 纸白#F5F3E9 | 1.81:1 | 同上 |
| 湖蓝#176B80 / 选中浅蓝#DBEBE9 | 4.95:1 | 可承载选中符号和文字 |
| 暖橙#E89246 / 选中浅蓝#DBEBE9 | 1.98:1 | 若作为必要进度图形应优化；结合题号仍须检查视觉辨别 |

WCAG非文字3:1要求针对识别控件/状态所必需的图形信息，并非所有装饰线都必须达到3:1。这里采用更明确的项目必要边界目标，不能仅凭浅边框比值断言整个产品违反WCAG。

色彩不以“只能三个十六进制值”执行。湖蓝、暖橙、纸白是三个主色家族，可有受控明暗；墨色和辅助灰是信息中性色。错误色小面积使用并配合错误图形和文字，不能成为另一套整屏主题。

### 5.3 动效与反馈

| 项目 | 拟定目标 | 证据 |
| --- | --- | --- |
| 按下响应 | 触碰后100ms内可见变化；静音时仍可识别 | 高帧率录像或带时间戳事件/渲染记录；不能靠目测截图证明时延 |
| 按压 | 约1—2逻辑单位下压或0.98—0.99缩放；避免文字模糊 | 所有控件实点，不只看主要按钮 |
| 页面过渡 | 建议180—260ms；不阻碍输入和阅读 | 录像；低性能设备需回看 |
| 通关反馈 | 建议500—900ms，能够跳过或迅速开始下一步 | 不允许强制等待长动画；不新增奖励系统 |
| 加载 | 有明确动画/进度；失败后有后备或可恢复入口 | 断资源、慢加载与恢复测试 |
| 动效克制 | 读题时题干/选项不漂移；减少动态模式下去除非必要动画 | 浏览器减少动态设置与小游戏自身可选机制分开检查 |

以上动效数值是设计目标，尚未在微信设备上测量。减少动态参考W3C交互动效原则，不表示当前Canvas已具备完整无障碍支持。

## 6. 关键页面与状态验收清单

### 6.1 页面级

| 页面 | 必须出现 | 重点判断 | 不应出现 |
| --- | --- | --- | --- |
| 主题首页 | 四主题真实名称、代表建筑/场景、各自进度 | 用户能辨认四种内容；入口是主要视觉任务 | 海报占满屏，四入口像页脚；四主题只有四种颜色 |
| 主题地图 | 四节点、清楚路线、当前/锁定/已完成、回退 | 路线与场景结合；当前节点和下一目标可辨；已完成点亮 | 多余节点；纯编号圆圈；未解锁和今日锁定混淆 |
| 答题页 | 题干、四选项、N/10、倒计时、确认；按题需要图/视频 | 读题优先；真实媒体与题意相关；短屏/长内容能读能点 | 每道题都贴同一张无关风景图；默认把装饰图当题图 |
| 首错复活 | 明确答错、一次复活、恢复原题、分享入口和返回 | 不用惩罚羞辱语言；说明分享未完成/失败不会恢复 | 返回前台自动显示分享成功；暗示无限复活 |
| 当日锁定 | 当前关卡名称、今日无法继续、明日再来、返回地图 | 玩家知道其他关卡不受这次锁定影响；正式日期由规则决定 | “今日全游戏无机会”；仅一个灰按钮无解释 |
| 结果页 | 得分、正确率、重玩、分享；通关后对应解锁/主题证书入口 | 分数与实际记录对应；第4关和最后16关有正确结果文案 | 第4关显示“进入第5关”；试玩结果冒充正式积分 |
| 排行榜 | 日榜/总榜、通关数/正确率、自己位置或未上榜说明 | 一眼可比较；长昵称/同分/空榜/加载失败有布局 | 虚构榜单和名次；假头像当真实玩家 |
| 证书 | 主题证书/总证书、对应完成条件、清楚名称 | 有纪念感但不变成塑料奖杯；长名字与分享裁切可读 | 未完成提前正式颁发；暗示无依据的官方背书 |
| 管理端 | 基础配置、四关配置、题库、复活、积分五模块 | 表单可读、错项定位；四选项/正确答案/难度/解析有清晰关系 | 将玩家端装饰照搬后台；难以分辨保存状态 |

管理端应复用语义色、字体与反馈规则，采用适合桌面表单的密度，不强行用375宽玩家画面的版式。

| --- | --- | --- |

## 7. 美术资产专项检查

### 7.1 每张场景的检查顺序

1. **实际尺寸**：先按手机显示尺寸看主次，判断画面是否拥挤、是否抢过题面和节点。
2. **50%缩略**：确认主形和主题仍成立。模糊成一团时，先减细节，不是加锐化。
3. **100%局部**：查关键建筑、道路、桥、水岸、人物/动物轮廓与拼接痕迹。
4. **灰度**：核查前中后景与当前节点的明度分离，不能只靠蓝橙色差。
5. **UI覆盖**：把真实文字、四节点、弹窗放上去，不只审一张裸背景。
6. **不同裁切**：320宽短屏、375基准、414/430宽长屏；记录被裁掉的主体。
7. **系列并排**：四主题的视角、线条、纹理和对象比例一致，但主题物件有区分。

### 7.2 专项记录表

| 检查项 | 通过条件 | 记录 |
| --- | --- | --- |
| 建筑/器物可信 | 关键结构合理；具体地方物件经核实 | 对象名、局部截图、内容审核人 |
| 笔触控制 | 同类对象轮廓/纹理密度相近；没有随机满屏颗粒 | 代表局部对照 |
| 景物与UI一致 | 同一套形状语言；图标有与场景对应的简化关系 | 场景与图标并排图 |
| 节点落点 | 四节点像属于路线/场景，不像后贴的广告标签 | 路线与节点叠加图 |
| 视觉重心 | 主体清楚；装饰不占据最重要操作位置 | 灰度与缩略图 |
| 空白用途 | 为UI预留的地方真正可用，非随意开一块空地 | 真控件叠放 |
| 源文件 | 原始提案、修订、导出、来源/使用依据可追溯 | 文件名与版本 |
| 生成式资产 | 有提示词/参考来源/人工修整与审阅记录 | 不以提示词或生成次数证明合格 |

一张好看的风景不等于一张好用的游戏地图。没有四个可承载关卡场景的落点、缺少路线层次、主题不明确时，应返回构图阶段重做。

## 8. 玩家观察与多人评审

### 8.1 小规模形成性测试

建议首轮6名目标年龄玩家：10—12岁3名、13—16岁3名。记录仅用于发现设计问题，不外推为“90%用户喜欢”等总体结论。按适当的监护授权与项目安排招募，记录不含不必要的个人资料。

| 任务 | 观察方法 | 本轮拟定目标 |
| --- | --- | --- |
| 识别四主题 | 看首页后说出每个主题大致讲什么 | 至少5/6无引导正确对应；记录误解主题 |
| 找到开始入口 | 从首页找出所选主题第一关 | 至少5/6在5秒内指出；这里测界面识别，不测网络加载 |
| 识别地图状态 | 指出当前关、未解锁和已完成节点 | 至少5/6无需只靠颜色也能解释 |
| 完成四选一操作 | 阅读适龄题，选一项并确认 | 6/6无需解释操作；知识答错不等于UI失败 |
| 理解失败规则 | 看复活和今日锁定状态后复述 | 至少5/6知道一次复活、恢复原题、只锁当前关 |
| 审美反馈 | 询问“更像游戏还是学习工具？哪里想点？哪里廉价？” | 记录原话、指向区域与改法；不诱导“是不是很高级” |

样本太少、年龄偏一端或缺少关键状态时，标“探索性观察不足”，不能算完成玩家验收。

### 8.2 评审分工

- 项目负责人：最终审美方向和是否符合需求，由用户确认。
- 美术/UI评审：按表独立评分，指出具体对象和页面；AI初评只是其中一种意见。
- 工程检查：提供尺寸、对比、真实触控/状态和设备证据，不决定美术是否好看。
- 内容审核：确认红色历史、人物、物产和地理表达是否正确。

不同评审者单项相差2分及以上时，不直接求平均掩盖争议。并排看证据，记下分歧与修订决策；必要时补玩家观察。
