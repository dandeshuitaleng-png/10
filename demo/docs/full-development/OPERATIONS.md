# 运行维护与恢复

当前支持Node.js 24.19与SQLite。DM8/TongRDS尚未取得指定环境，不把下述演练称为国产数据库通过。玩家网页、微信入口和管理后台共用游戏API；微信真机需要另行配置可访问的HTTPS服务。

## 启动与保存

在游戏工程目录执行 `node server/start.cjs`。默认只监听本机127.0.0.1:63112，运行数据位于工程外的 `../.rural-quiz-runtime/`，以避免微信开发工具因存档变化重新编译。管理员随机凭据、数据库和备份均应保持本机私有；不放进静态目录或交付包。

可配置项：`PORT`、`QUIZ_HOST`、`QUIZ_DB_PATH`、`QUIZ_MODE`、`QUIZ_ADMIN_USERNAME`、`QUIZ_ADMIN_PASSWORD`。生产模式还须在启动适配器注入可信身份、分享验证和同步接收端；仅修改QUIZ_MODE不会完成外部接入。正式域名、TLS与网关设置依部署环境确认。

### 本机连接被拒绝

微信或网页报告`127.0.0.1:63112`的`ERR_CONNECTION_REFUSED`时，先检查本机服务是否仍在运行。微信开发者工具与游戏服务是两个独立进程，打开或编译游戏不会自动启动服务。在`demo`目录执行`node server/start.cjs`，确认`/api/health`返回成功，再在游戏中重新连接或重新打开排行榜；沿用原数据库，无需清除玩家存档。若端口已被其他进程占用，先确认占用者，不要直接终止未知进程或修改正式域名校验设置。

2026-10-14本机恢复记录及排行榜积分修复见`交付/趣味闯关_排行榜修复说明_20261014.md`（位于工作区根目录的交付文件夹）。该补丁只记录本次服务端检查和浏览器/微信排行榜请求，2026-10-13完整包和其历史验证保持原样；应用补丁后的完整游戏和真机验收须另行记录。

## 一致备份

使用数据库备份接口，避免只复制运行中的主文件而漏掉WAL事务。实现依据 [Node.js SQLite备份接口](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html#sqlitebackupsourceDb-path-options)。备份文件含游戏记录和会话数据，文件及校验清单均为600权限；报告只输出各类记录数量。

```sh
node scripts/maintain-data.cjs backup ../.rural-quiz-runtime/quiz.sqlite ../.rural-quiz-runtime/backups/quiz-20261012.sqlite
node scripts/maintain-data.cjs check ../.rural-quiz-runtime/backups/quiz-20261012.sqlite
```

目标文件必须不存在。工具先建立私有暂存快照，完整性检查通过后再发布，并记录SHA256。校验文件为备份文件旁的 `.json`。复制备份时一同复制校验文件；不将玩家记录写入公开日志。

## 恢复演练与实际恢复

```sh
node scripts/maintain-data.cjs restore ../.rural-quiz-runtime/backups/quiz-20261012.sqlite ../.rural-quiz-runtime/recovered/quiz.sqlite
QUIZ_DB_PATH=../.rural-quiz-runtime/recovered/quiz.sqlite PORT=63113 node server/start.cjs
```

恢复只允许新目标，校验哈希、数据库完整性和记录数量后再恢复。先在另一端口查看记录，确认后停止原服务、切换数据路径，再按既有入口启动。保留原数据库和备份，以便回退。切换到恢复点会丢弃该点之后的新记录，应由实际维护负责人确认恢复点后操作。

管理员文件不是数据库备份的一部分。配置自有管理员凭据，或按既有安全渠道保管原凭据文件；不要复制至玩家可访问位置。恢复数据库包含当时有效的会话，如需应急撤销，应按实际身份/会话方案处理。

本轮 [真实恢复演练](../../design/full-development/evidence/operations-report.json)：隔离游戏先完成4关、75分、1张证书和一个活动挑战；在线备份后源库继续计分；恢复并重启后，原会话、进度、证书、原题和截止时间均保留。未修改用户正在使用的存档。

## 日常核查

`/api/health` 与后台概览可查看环境、运行存储和接入条件。后台“操作与同步”显示待回传记录和操作日志；没有接收端时不会显示同步成功。实际接收端接入后按事件编号幂等处理，并核对游戏通关记录与接收端认可记录。

前台只接收当前题与已提交题解析。玩家不能直接写积分、截止时间或通关状态；管理员修改题目会撤销审核，已开始的挑战保留原版本。更新客户端或规则后保留一份可恢复交付包与数据库备份，再进行完整验证。

## 本机并发基线

[并发记录](../../design/full-development/evidence/performance-report.json)使用24个独立账号并发完成10题。共553个请求全部成功，重复末题后仍只有24条积分记录，合计240分；账号进度与榜单检查通过。最新本机HTTP+SQLite响应统计见记录中的`latencyMs`，不沿用旧版测量值。单进程、分轮提交，不能据此确定生产容量或手机帧率；正式性能目标仍需按部署资源与约定规模验证。


## 0.3.0目录升级

升级前按上面的维护工具备份到未存在的新文件，再启动新源码。首次启动会在单一事务中升级活动配置并保存目录版本；不会清空用户、积分、通关、旧证书或进行中的挑战。旧挑战保留原题目和截止时间，旧复活记录迁为0/1次。迁移失败回滚并停止启动，先保留原库再排查。

升级后检查配置`schemaVersion:2`、默认四主题16关与已确认规则、已获证书及活动挑战是否保留。动态配置和JSON导入是活动内容更新，不是数据库恢复；导入不接受文件中的批准状态，题库只有明确选中时才导入并撤销旧内容审核。

新设置只作用于之后开局。在途旧局可仍按原日上限结算，因此不能用新上限回写或重算旧积分。指定DM8/TongRDS尚未实测；SQLite迁移与恢复记录不能替代指定环境。
