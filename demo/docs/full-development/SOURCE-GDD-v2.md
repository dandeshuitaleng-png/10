**范围控制：**拖拽、排序、答案输入、动态难度、Boss、宝箱奖励、星级、连胜奖励、额外节点等分享对话中的扩展建议不纳入本次交付。不得将“四选一知识答题”替换为另一类解谜游戏，也不得减少四主题、16关、榜单、证书或五项管理模块。视觉优化、动效与音效应服务现有规则，不能增加玩法或改变计分、解锁与复活条件。

**需求与建议分开：**下文的“建议”“待确认”均不是用户已经确认的规则；时限、超时、分享有效判定、复活额度周期、正确率口径、重玩积分和榜单并列等，仍按第8节保留，不以原型默认值或分享建议补成正式要求。约20天、每5天阶段交付属于项目进度约束，不构成增删功能的授权，也不等于已通过平台审核。

## 1. 玩家体验与定位

玩家从四个乡村主题中选择兴趣方向，在每个主题的四级地图上逐步挑战知识题。每关随机抽取10题，每题四个选项，全部答对后解锁下一关并获得积分。完成主题得到专属电子证书，完成全部16关得到“乡村知识闯关王”总证书。

四大主题：十步芳草、千年文脉、金色产业、青山绿水，分别承载红色底蕴、人文历史、物产特色、生态风光。具体题目、地标、产业和故事依内容审核结果确定；不以示意图中的建筑招牌作为已批准的关卡名称。

首次进入展示“每关10题，全答对即可通关；答错可分享复活1次，分享成功后重答当前题；复活后再错，本关今日锁定，明日再来”。当日锁定仅作用于当前关卡（用户已确认），其他可进入关卡不受影响；分享条件的正式措辞待第8节机制明确后再定。

首页不让玩家先阅读整份规则；进入关卡前须明确展示倒计时、题数、积分、通关条件和剩余机会。失败反馈说明原因，避免羞辱性音效或文案。已通关成果不因失败扣除。

## 2. 主题、关卡与积分

| 主题 | 关卡 | 每关挑战题数 | 对应积分 | 主题完成奖励 |
| --- | --- | --- | --- | --- |
| 十步芳草 | 4级 | 10题 | 10/15/20/30 | 专属电子证书，“红色故事通”为用户示例名称 |
| 千年文脉 | 4级 | 10题 | 10/15/20/30 | 专属电子证书，名称待定 |
| 金色产业 | 4级 | 10题 | 10/15/20/30 | 专属电子证书，名称待定 |
| 青山绿水 | 4级 | 10题 | 10/15/20/30 | 专属电子证书，名称待定 |

每主题单次完整通关积分合计75分，四主题合计300分。这是16关各计一次的算术总量；积分是否仅首次通关发放仍待确认，不能把300分直接称为永久积分上限。

第1关：基础认知，以记忆识别为主。第2关：进阶理解，以理解应用为主。第3关：深度应用，以分析判断为主。第4关：综合挑战，以高难推理与综合信息为主。四级均需10题全部正确，不能采用旧版“完成回顾即解锁”。

16关每轮共160个作答位置，不等于题库只需160题。随机挑战需要各关配置充足题池；最低为每关10道有效题，题池扩容量待内容制作计划确定。现有240题目标不自动继承。

难度标签采用用户要求的基础/进阶/综合三个值；第3关“深度应用”通过题型与关卡归属区分，不擅自新增第四个难度标签。

## 3. 玩家页面与主要流程

主题页 → 主题关卡地图 → 关卡介绍 → 单题作答 → 判定 → 下一题 / 复活弹窗 → 通关或失败结果 → 地图 / 重玩 / 分享。

### 3.1 四主题入口

四张入口具有一致控件结构，分别显示主题名、简短内容介绍、代表建筑或场景、已通关关数（0/4至4/4）、继续入口。建议四主题首关均开放，主题之间不互相锁定；此为待确认设计建议。

四主题可以有不同景物和点缀色，但共享湖蓝主行动、暖橙奖励、字体、图标、圆角与状态语言。总榜/日榜入口清楚可见，证书入口在已获得后突出，不将示例图上的宝箱增加为新玩法。

### 3.2 关卡地图

每主题四个节点沿清楚路径按顺序组织，显示关卡名称、序号、难度、积分和状态。状态包含可开始、挑战中、已通关、未解锁、今日锁定。已通关点亮；锁定节点可点击查看原因。不同状态不能只用颜色区分。

关卡介绍显示10题、全对通关、单题时限、该关积分和复活额度。未配置时限或题池不足的关卡不能上线为正常可玩状态。关卡名称由管理端配置，具体文案待内容团队确认。

### 3.3 答题页

信息顺序：返回/暂停与主题关卡 → “第N/10题”及进度条 → 倒计时 → 题干与必要图片/视频 → 四个选项 → 确认答案。

建议选中后可更改，点击确认才判定；倒计时到期与提交竞争时只接受一个合法结果。答案提交后锁定选项，正确提示加简短解释，用户点击进入下一题。解释阅读阶段不消耗下一题时间。

视频须可播放、暂停和重播；视频观看是否占答题时间、时长上限、资源加载失败处理均待确认。建议题目与必要资源准备完成后再开始计时，避免加载耗掉玩家机会。

本版不继承旧版跳过、免费提示与五题小结规则：跳过与“10题全部答对”冲突。若保留提示，需另定是否影响正确率和排名；在未确认前不把提示入口纳入正式答题样板。

### 3.4 首次答错与复活

按用户要求，每关答错可分享复活1次。弹窗说明本次错误、复活剩余次数、分享入口及退出入口。复活后恢复当前题作答机会，不直接进入下一题、不直接标记答对；此前正确题记录保留。

必须明确：玩家看过正解后重答原题很可能直接选对，因此复活弹窗暂不自动展示正解；完整解析在不再恢复当前题的结果/回顾阶段展示。此为建议，需业务确认解释展示时机。

“分享成功”判定尚需平台验证；调用分享或从后台返回不等于证明实际分享成功。实现前须确定可验证条件和取消/失败处理，不用模拟成功替代真实机制。若目标平台不能支持所需判定，应先调整产品规则，再实施复活发放。

复活发放和消耗须有明确记录；重复点击、反复切后台、刷新、重新打开弹窗不能多领。每关1次究竟按每日、每次挑战还是永久计算，见待确认表。

### 3.5 再次答错与失败结果

复活后再次答错仅锁定当前关卡（用户已确认），显示“本关今日无答题机会，明日再来”；其他已开放关卡可继续挑战，同时显示锁定对象、可恢复的日期/时间和已保留成果。失败结果展示本次进度、正确/错误次数、解析回顾及返回入口；锁定中的重玩按钮说明原因。

退出而未使用复活的挑战如何处理、首次答错后拒绝分享是否立即锁定，尚未给出规则，不由开发者自行推定。

### 3.6 通关结果、重玩与分享

本次10题均正确后，结果展示关卡通关、所得积分、正确率、下一关、返回地图、重玩、分享。主行动优先下一关；末关改为查看主题证书。

重玩入口遵循日机会规则；是否重玩发积分以及是否重抽题待确认。未正式实现分享时不展示假成功提示。

复活情况下不能只显示最终纠正后的100%：建议同时显示“通关进度10/10”和真实首次作答正确率，并标注是否使用复活。计算口径见第8节。

### 3.7 证书

完成单主题4关时获得一张主题电子证书；全部4主题16关完成获得“乡村知识闯关王”总证书。证书不代表正式学历或教育资格。

展示内容建议：证书名称、主题、完成日期、四关完成记录、查看/保存/分享入口。姓名、头像、编号是否需要及来源待确认，不默认收集实名信息。图片保存需使用平台真实能力并处理拒绝、失败与重试。

证书由已确认通关记录触发，重复进入不重复发放；原徽章可作为小型视觉标识，但不能代替需求中的电子证书。

### 3.8 排行榜

日榜与总榜，主要按通关关数、其次正确率排序。显示排名、展示名、通关关数、正确率及自己的位置。并列规则、重玩记录选择、日界线、统计对象和有效记录范围待确认。

推荐采用服务端认可的通关与作答记录；本地修改不能直接改变榜单。访问失败显示重试与返回，不伪造玩家或排名。若未接入真实服务，只能明确标记演示数据。

## 4. 管理端功能与发布要求

| 模块 | 可编辑内容 | 保存/发布检查 |
| --- | --- | --- |
| 基础配置 | 主题、互动名称、封面图、背景色 | 主题来自四项固定值，文本完整，图片可访问，颜色与文字可读 |
| 关卡配置 | 每主题4关、名称、顺序、启用、通关积分 | 序号不重复，依赖关卡有效；停用中间关不得留下无法解释的解锁断点 |
| 题库管理 | 增删改查；题干、4选项、正确答案、解析、难度 | 恰好4项、唯一正确答案、解析非空、归属明确、审核通过 |
| 复活配置 | 1次额度、分享语、分享图 | 额度与产品规则一致；分享资源有效；验证方式未确认时不能声称可真实判定 |
| 积分配置 | 第1至4关10/15/20/30分 | 整数、非负；变更后的旧记录处理明确 |

为支持前端图片/视频题，题库还需素材类型、资源ID/地址、是否必需、题目版本、主题与关卡归属、启用状态。为支持倒计时，需增加明确的时限配置位置；这两项是由前端要求推导出的管理端缺口。

建议草稿、预览、发布分开。已开始挑战固定题目与规则版本，管理端修改不能中途换掉正确答案或积分。删除使用中的题采用停用或保留历史版本，保证排行榜、解析和旧记录可追溯。

随机抽题：仅从当前关卡已启用且审核通过的池中取10题，同次挑战不重复；不足10题不能开局。失败后的换题与跨次避重复策略待确认。

## 5. 状态与中断处理

状态：可开始 → 准备资源 → 作答 → 已提交 → 正确反馈/等待复活 → 复活作答 → 下一题/通关/今日锁定。

| 情况 | 要求 |
| --- | --- |
| 提交与超时同时发生 | 单次判定，不多扣机会、不重复计分 |
| 分享取消/失败/返回 | 保持等待状态，不凭返回时间冒充分享完成；正式行为待机制确认 |
| 切后台/锁屏 | 计时策略待定；不能通过退出反复获得满时限 |
| 断网 | 不丢已认可记录；榜单不可用不伪造；失败是否扣机会需明确 |
| 图片/视频必需但加载失败 | 重试/退出，建议准备阶段不扣答题机会 |
| 应用重启 | 恢复题序、题号、时限、已提交记录和复活额度，防止重复领积分 |
| 跨日 | 按统一可信日期重置允许重置的额度，范围需确认；不能凭本地改时绕过限制 |
| 规则更新 | 本次挑战固定版本，后续新挑战采用新版本 |

恢复、积分和发证不能只靠客户端成功提示作为证据。存储失败需明确提示，保存成功与通关成功应分别确认。

## 6. 美术与参考图的使用边界

保留示意图的四个主题环境、四个可识别建筑/场景节点、一个突出主行动和主题识别符号。取消塑料3D、金属高光、厚重立体字与满屏高饱和表现，采用统一平面2D描边与色块规则。

配色沿用湖蓝＋暖橙：湖蓝用于开始、确认、继续，暖橙用于积分与通关亮点。红色文化内容可有克制红色点缀，不把整个主题UI改成另一套视觉系统。

效果图写“12道”，本需求明确“10题/关”，开发与新版画面一律采用10题。效果图中的题数、招牌、动物、宝箱不自动进入功能或事实内容；生态与文化题素材需按实际地区审核。

此前“第1/5题、书香小达人”的视觉样板仅用于观察画风，不能作为本版内容验收稿。下一张正式样板应改为新主题、“第1/10题”、倒计时、4选项与新复活状态，并采用经审核的新题干。

## 7. 验收与实施顺序

先做一个主题的完整10题挑战原型：默认、选中、倒计时、正确、首次错误、复活、再次错误锁定、通关结果。确认规则后接入其余主题与管理端、可信积分和榜单、证书。

验收必须包含：四主题各4关；同次抽题无重复且恰好10题；每题4选项与唯一正解；全对才解锁；复活最多1次且只恢复当前题；复活后再次错误仅锁定当前关卡当日；同一次通关结算不重复发积分（重玩是否发积分仍待确认）；日榜与总榜符合确认后的统计口径；主题与总证书条件正确；图片/视频失效、超时竞态、分享取消、中断跨日与规则更新均有真实操作证据。

10–12岁和13–16岁分别试玩。观察读取倒计时、错误与复活说明是否清楚，是否理解锁定范围，是否能找到下一关；静态效果图不能证明这些交互通过。

## 8. 待确认的执行规则

| 问题 | 原文已确定 | 尚未确定 / 建议 |

| 单题计时 | 有倒计时 | 时长、不同难度时长、超时是否等同答错、后台是否继续 |
