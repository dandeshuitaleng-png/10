# 管理后台操作说明

更新：2026-10-13。管理端已按 1012 版活动配置范围提供动态主题、关卡、题数、复活额度、关卡积分、每日积分上限、证书与分享内容操作。原活动默认值保留：四主题、各四关、每关十题、30 秒、每次挑战复活一次、10/15/20/30 分、首次通关发分、每日积分不限、北京时间零点日界线。

打开 `/web/admin.html` 或 `/admin`，使用部署时配置的管理员账号。首次随机账号的私有保存位置见根 README。玩家账号无法访问管理接口；后台使用 HttpOnly 管理员会话。退出后台只撤销管理员会话，不影响玩家进度。

## 主题与活动外观

基础配置可维护活动名称、主封面、背景色，以及每个主题的稳定编号、名称、排序、介绍、封面、地图图像、背景色、主题证书名称和正文。

点击“新增主题”会先创建未保存的表单。新主题默认未启用；可编辑小写英文编号，再点击“保存基础配置”一并保存。主题编号一旦保存就不可更改，名称与顺序可以编辑。顺序不能重复；交换顺序时，先改好两个主题再一起保存。没有关卡或有效题目的主题仍需继续配置，新增主题本身不代表可正常挑战。

取消“启用主题入口”会软停用主题，保留题目、关卡与历史挑战。当前界面不物理删除已经保存的主题。未保存的新主题可以直接移除。

封面与地图使用已部署的受控站内地址或 HTTPS 地址。增加独立内容主题、地标或图片/视频题时，应提供与内容相符的素材；已有四套场景不自动代表新增主题的当地实景。素材加载失败会提示检查地址，保存时仍由服务端验证路径与格式。

## 关卡、题数与奖励

关卡配置按照后台主题目录显示，不再限制每主题四关。每个关卡可设置名称、排序、启用、首次通关积分、每次挑战题数和难度说明。已存在的关卡编号与主题归属保持稳定，不能通过改名或排序搬迁历史记录。

“新增关卡”打开独立表单，默认十题、未启用。填写稳定的小写编号、名称、所属主题、顺序、题数、积分与难度说明后保存，再到题库管理关联题目。顺序为正整数，在同一主题内不能重复，不要求连续。显示、解锁和下一关按实际排序执行，不能依赖编号中的数字。

保存主题内的全部关卡可以同时交换两个关卡的顺序。停用前关时必须同时停用其后续关卡，避免无法解锁。每行“停用此关及后续”需要确认，一次停用选定关卡及后续启用关卡；历史挑战与题目仍保留。该操作会重新读取本页数据，未保存的本页编辑应先保存。

有效题池必须不少于所配置题数，否则服务端阻止开局。正式模式只抽取审核通过且已启用的有效题。授权体验开放的原源题仍保持待审核，不等于正式内容批准；新增、编辑与导入题目不会自动继承这种授权。

技术输入限制：1—100 个主题、总计最多 1000 个关卡、每关 1—2000 道题、积分为 0—1000000 的整数。这些限制用于资源与输入保护，并不代表已批准的业务玩法规模。

## 题库与审核

1. 按当前主题、关卡、审核状态或题号/题干搜索。新增题目填写四个不同选项、唯一正确答案、解析、基础/进阶/综合难度及明确归属。
2. 图片/视频题填写已部署的地址。打开编辑或审核面板检查素材与题目是否相关；审核面板同时展示四选项、正解、解析与来源。
3. 保存后进入待审核。修改已审核题会撤销旧审核及启用状态，正在进行的挑战继续使用开局时版本。
4. 审核前核对事实来源、干扰项、适龄性、难度与素材。填写审核说明，实际通过后再选择启用。服务端记录当前管理员与时间，不从导入文件继承审核人。
5. 主题尚无关卡时，新增题目界面会提示先配置关卡，避免产生无归属题目。

题库“导出 JSON”保留完整题目数据。“导入 JSON”接受题目数组或 `{questions:[…]}`，整批校验成功后事务保存。相同题号会更新原题；新题与更新题均强制待审核、未启用。导入前应备份、检查题号与关卡归属。即使文件包含批准字段，也不能直接批准内容。删除需要确认，旧挑战保留题目快照；源工作簿不由后台自动修改。

## 复活与每日积分上限

复活配置可编辑每次挑战额度、复活分享语与分享图，默认一次。允许填写 0—100 的整数；0 表示不允许复活。可信分享成功后重答当前题，额度耗尽后再次错误只锁定当前关卡当日。额度周期保持每次挑战。

正式分享需可信验证，打开分享界面或返回前台不会自动成为分享成功。体验环境中的测试复活始终明确标识，不充当真实分享证据。

积分页可切换“不限制每日积分”与非负整数上限。默认不限制；0 表示当天不发积分但仍可答题、通关。各关奖励通过关卡配置修改，重玩仍不重复发分。

有限上限的体验策略为 `truncate-reward`：首次通关按当日剩余额度发分，额度耗尽仍记录通关，超出部分不补发。多次复活策略为 `until-limit`：剩余额度内可继续分享重答，耗尽后再错锁定。这些新配置策略未自动成为正式批准规则。

**新设置适用于之后开始的挑战，进行中的挑战保持原规则。** 题数、时限、复活额度、关卡奖励、每日积分上限与证书条件均随开局冻结。例如先开了不限积分的旧局，再改为每日五分，旧局仍可按原不限规则结算；当前新上限不能回写旧局。管理端明确显示此边界，已入账积分也不会被配置修改重算。

改变活动结构、顺序、题数、奖励、时限、复活额度或每日上限会由服务端撤销原玩法批准。后台显示“规则待确认”，正式模式受门禁限制。管理表单不提供自行批准玩法的开关；恢复旧值也不等于已完成重新批准。仅保存与原默认等值的设置，或更新不影响规则的文案/素材，实际批准状态以服务端返回为准。

## 证书与旅程分享

基础配置中可编辑共同证书抬头、总证书名称与正文、落款，以及结果/旅程分享的标题、文案、图片。主题证书名称与正文在主题卡片内维护。

所有正文均为普通文字，不支持 HTML 或模板变量。已颁发证书保留颁发时的内容与条件；新增证书按挑战冻结的目录条件发放。复活分享与旅程分享分开配置，不把结果分享当作复活成功的证明。

## 活动配置备份与恢复

基础配置下方的“导出活动配置”下载 `{config,levels}` 及格式版本、导出时间，包含主题、关卡、规则、证书与分享内容。管理端的活动导出文件不包含题库，题库使用独立按钮导出，以避免配置恢复意外重置题目授权或审核。

“导入活动配置”先选择 JSON 并查看主题、关卡、题目数量，然后勾选已备份和确认导入。默认仅导入配置和关卡。外部文件若带 `questions`，只有明确勾选“同时导入文件中的题目”才会发送；这些题目仍强制待审核、未启用。整个活动导入由服务端事务校验，失败不会保存半份配置。

遗漏的历史关卡会保留为停用，不能用导入删除历史挑战；旧局继续自己的快照。配置文件中的批准状态不能绕过服务端规则审核。恢复后重新核对主题入口、题池容量、启用和批准状态，再开放新挑战。

## 操作与同步

概览显示真实题目、未批准内容、通关与发分统计，以及当前主题/关卡范围、复活、题数、每日上限和规则批准状态。操作与同步显示管理审计及待同步事件。

没有甲方接收端时，重试按钮禁用，通关事件保留待接入。接收端明确确认后才标为已同步；失败事件保留错误及尝试次数。后台不会把缺少接收端视为已同步成功。

操作说明已经提供；实际培训、甲方内容签审与平台正式验收需单独形成证据。遇到连接失败，先刷新核对操作是否已经保存，再重试；批量恢复与生产变更按维护说明和负责人确认的恢复点执行。
