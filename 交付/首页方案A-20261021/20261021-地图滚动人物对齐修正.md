# 地图滚动时人物缩放与漂移修正

人物继续跟随所属关卡，使用已确认的 A 方案、原始 PNG 和局部动作。本次仅修改浏览器预览适配器，不改变地图、底座、脚部定位、业务接口或玩家数据。

## 本次复核结论

此前修复不完整。`renderNode()` 会为所有 Canvas 注入 `750×1000` 默认尺寸。动画器先按显示尺寸与像素倍率建立缓冲、设置缩放；滚动、点击或状态更新触发 `morph()` 后，这两个默认值又被写回。设置 Canvas 宽高会清空绘图状态，因此后续人物按错误比例显示，造成缩小和漂移。浏览器实测春季人物脚部上移约 20.67 CSS px。

上一轮只保护了“删除 width/height”路径，其测试手工构造的下一帧没有默认尺寸，没有经过真实 `renderNode()`，因此未能发现覆盖路径。原先关于问题已解决的结论应以本记录为准。

## 修正

- 人物 Canvas 不再套用证书、分享画布使用的通用默认尺寸，由动画器根据显示区域与像素倍率管理。
- `morph()` 对已由动画器接管的画布，同时保护尺寸属性的删除和赋值；其他属性照常更新。
- 证书和分享画布继续保留默认值及各自渲染器的尺寸设置。
- 静态图、动画与关卡仍使用相同坐标关系，不新增滚动补偿、不固定人物到屏幕、不反复重建动画器。

## 验证证据

- 红绿测试：读取真实人物 WXML，经过实际 `renderNode()`、`morph()` 和人物绘制器。修复前两项失败（`750 !== 76`、`750 !== 152`），见 `scroll-buffer-before.log`；修复后动作、布局及画布相关 28 项通过，见 `scroll-buffer-regression.log`。涵盖四季、1/2/3 倍像素密度，每组 40 次更新，以及无默认尺寸、显式错误尺寸和证书/分享画布。
- 浏览器：支持的浏览器 CDP 通道运行 `tools/browser-mascot-scroll-probe-20261021.js`。四主题 × 四季 × 320/375/430 CSS px，共 48 组、4,800 个 requestAnimationFrame 样本。脚部与原图应有落点的最大误差低于 0.241px；人物与底座容器的相对位置、静态/动画显示区域和缩放矩阵稳定。每组连续往返滚动、重复点击、到边界后返回，同时检查停止动画时画布已清空。详见 `scroll-buffer-browser-checks.json`。
- 浏览器交互补查：20 次真实按钮点击均触发，随后滚动轮输入检查尺寸和落点；无浏览器控制台错误。`scroll-buffer-browser-after.png` 为红色主题点击后滚动的实际截图。
- 微信模拟器对照：冻结实际动作帧和静态图分别滚动 40px，误差为 0.086px 和 0.165px，见 `scroll-alignment-buffer-fix.json`。另复跑四季各 100 次批量调用及随后单次点击、四主题点击、原生 WXML 触发、后台和弹窗暂停，9 项通过，见 `click-motion-native-checks.json`。底部裁切检查测得地图下方人物青色像素为 0，见 `mascot-clipping-buffer-fix.json`。
- 全部浏览器矩阵使用隔离评审场景及真实 DOM/Canvas。矩阵滚动通过设置 DOM scrollTop 产生浏览器滚动事件，不等同于实体手指惯性滚动或性能测试。实体 iPhone/安卓微信本轮未测。
