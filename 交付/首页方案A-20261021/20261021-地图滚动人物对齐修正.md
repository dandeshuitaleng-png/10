# 地图滚动时人物对齐修正

用户确认：人物仍跟随对应关卡，修正滚动中的错位和漂移，不改为屏幕固定人物。

问题位于浏览器预览适配器 `preview/v4-runtime.js` 的 DOM morph。动画器运行后给 Canvas 设置了 width/height 绘图缓冲属性；滚动引起页面刷新时，模板没有这两个运行时属性，旧逻辑便把它们删除。绘图缓冲回到默认尺寸，同时清空缩放矩阵，后续人物帧因此与原图和关卡比例不一致。

修正：对已由人物动画器接管的 Canvas，保留其运行时 width/height；其他声明属性继续正常更新。没有改变地图、底座、人物站立坐标、滚动逻辑或动作曲线。四套独立工程的预览适配器同步修正。

验证：

- 修复前 `node --test tests/preview-mascot-scroll.test.cjs` 稳定失败：一次滚动刷新将 welcome 画布从 76px 重置为 300px。记录 `scroll-preview-before-regression.log`。
- 修复后覆盖四个原始季节形象、1/2/3 三档像素倍率，各 40 次刷新；同一帧的绘图缓冲尺寸、Canvas2D 矩阵、PNG 像素结果和实际滚动值均保持不变。此测试运行真实 morph 与真实人物渲染器，DOM 属性桥使用测试替身；不记为浏览器视觉验收。
- 连同人物动作与页面布局，共 26 项回归通过，见 `scroll-preview-regression.log`。
- 原生对照在修复前即通过：冻结实际动作帧和静态图分别滚动 40px，图像与原生人物节点的相对位移误差分别为 0.086px、0.165px。记录 `scroll-alignment-before.json` 及截图。它只验证隔离模拟器，不等于实体手机验收，也不是浏览器复核。
- 浏览器控制在 Work 设置中关闭，本轮未绕过该设置；通过 HTTP 校验当前预览确实服务修正后的适配器，新链接使用 `20261021-scroll-anchor` 以重新载入页面。

问题预防：声明式页面更新应明确保留由绘图器管理的 Canvas 状态；滚动回归应覆盖绘图缓冲和坐标变换，不能只检查人物容器的边界矩形。
