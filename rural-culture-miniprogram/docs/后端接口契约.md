# services 接口契约

> 历史/阶段记录：以下保存当时的规则、方案与验证范围。当前仅维护 A 方案，四套 HTTP 数据链已接通，题库不设审核模块；旧接口、旧报告及提交前状态不作为现状结论。当前实现和检查入口见 [当前工程状态](CURRENT_STATUS.md)。

生产统一返回 `{ ok: true, data: ... }`；失败返回 HTTP错误码及 `{ ok: false, message: '面向用户的错误信息' }`。所有写操作由当前认证用户发起，不采信客户端积分、答案、复活次数、完成状态或日期。Authorization使用Bearer Token；本原型尚未实现正式登录。

| 方法 | HTTP | 路径 | 输入 |
| --- | --- | --- | --- |
| getHome | GET | /home | 无 |
| getThemes | GET | /themes | 无 |
| getTheme | GET | /theme | themeId |
| getProgress | GET | /me/progress | 无 |
| startSession | POST | /sessions | chapterId |
| getSession | GET | /session | sessionId |
| submitAnswer | POST | /answers | sessionId, questionId, optionId或null, requestId |
| claimRevival | POST | /revivals/claim | sessionId, token |
| nextQuestion | POST | /sessions/next | sessionId |
| getResult | GET | /result | sessionId |
| getCertificates | GET | /me/certificates | 无 |
| getLeaderboard | GET | /leaderboard | scope: daily / total |

会话包含 `sessionId, theme, chapter, position, total, deadline, serverNow, status, remainingRevivals, dailyLocked, question, feedback, revivalToken`。deadline和serverNow为毫秒时间戳，前端仅显示倒计时；超时认定由后端执行。状态：answering、reviewing、revival、pending、locked、completed。

题目仅包含 `id, text, options: [{id,label,text}], media`，不含标准答案、答案索引或未作答解析。media为null或 `{ type:'image'|'video', src, alt? }`。正式素材必须配置合法资源域名并取得授权。提交后feedback可以包含correct、timedOut、selectedOptionId、correctOptionId和explanation。

复活token由服务端发放并绑定用户、会话、日期和资格，不能由前端生成。微信分享触发及回到前台只能表示交互动作，不能证明分享完成。正式业务需确定可验证资格，未满足时返回pending或拒绝，不因分享调用直接增加次数。

积分写入以用户与章节为唯一奖励键，重复提交、重复结算或重读不重复发放。nextQuestion和领取结果也应提供服务端幂等语义。排行每日周期使用Asia/Shanghai；同分名次的正式规则需由业务确定，当前演示采用稳定排序。

证书仅返回已完成用户获发的证书，包含id、themeId、title、name、date、number、description、color。总证书themeId为all。正式编号必须全局唯一，并可由后端验证；演示编号仅供UI展示。

本阶段不接正式数据库，认证、持久化、限流、可靠分享资格和正式证书校验仍需后端实现。
