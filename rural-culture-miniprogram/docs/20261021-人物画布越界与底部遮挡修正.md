# 人物画布越界与底部遮挡修正

用户反馈人物出现在地图下方，遮住“开始第1关”按钮。使用隔离微信工程复现：红色主题首页、人物停止、地图滚动后，底部出现原人物的蓝色面部像素。

问题位于 `services-v4/mascot-canvas.js`：此前停止动画仍调用 `render(0)`，把原图重新画进画布。静态原图与画布静止帧因此同时存在；原生画布越过滚动裁切或遮罩时，残留像素会盖到地图外。修正为静止时只使用原始图片，停止动画、后台暂停、组件卸载和渲染异常时同步清空画布。同时收紧播放条件：人物只有完整进入地图可见区才播放；滚动到边界、部分露出时使用正常裁切的静态原图，避免动作画布跨过固定操作区。连续动作绘制、原始素材和手部形变不变。

验证先失败再修复：

- `tools/check-mascot-clipping-native-20261021.cjs before`：底部检测到 2477 个符合人物面部蓝色范围的像素，断言失败。像素阈值仅用于这个红色页面的确定性复现，不作为任意页面的通用图像识别。
- 同命令 `after`：底部对应像素为 0，截图中按钮完整。
- `tests/local-mascot-motion.test.cjs` 新增真实渲染器生命周期回归，初始静止、播放后暂停、hide/detach 使用的 stop 均须留下透明画布。修复前失败，修复后通过。
- 四季每次批量 100 次点击后再单独点击一次、四主题点击、后台/弹窗的地图画布停止检查及真实 WXML tap 回归记录见 `click-motion-native-checks.json`。字体修正另见同目录标题说明。

原生模块在首次热刷新后仍持有旧 renderer；通过读取实际 animator.update 函数确认旧分支仍有 render(0)，重新打开隔离窗口后才记录修复结果。没有将旧模块上的失败结果误记为新代码通过。

证据位于 `qa/home-designs-20261021/mascot-clipping-{before,after}.{json,png}` 及 `mascot-clipping-*-regression.log`。微信模拟器、源码测试与浏览器 HTTP 校验各自记录；本轮未做实体手机验收。

原生自动化桥接不支持直接序列化 Canvas 节点做 getImageData 采样（An object could not be cloned）。因此原生通过截图采样复现底部残影，通过 animator 状态核对暂停；画布清空由实际 renderer 回归锁定，不把无法取得的原生 RGBA 读回记为通过。
