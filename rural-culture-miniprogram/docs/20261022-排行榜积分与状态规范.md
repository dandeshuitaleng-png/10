# 排行榜、积分明细与状态规范

> 阶段记录：本文保留 2026-10-22／23 的设计决策与当时检查结果。当前规则见 [维护索引](MAINTENANCE.md)，代码质量和远端检查见 [本轮修复记录](20261025-代码质量修复与验证.md)。文中的 qa/ 路径为本地历史存档，未随仓库全部上传，不能当作本轮重新验收。

2026-10-22。延续四主题既有插画、横幅和轻量文化学习风格，统一列表、数字与状态卡片。母工程及四套独立工程已同步。

## 页面规则

| 组件     | 当前规则                                                                                       |
| -------- | ---------------------------------------------------------------------------------------------- |
| 排行切换 | 每日榜与总榜同宽，44px 点击区，浅主题色表示当前项，加载期间禁用切换                            |
| 本人排名 | 放在榜单前；左侧排名、右侧积分，先看清自己的学习位置                                           |
| 排行列表 | 名次 28px、头像 28px；学习者列标题对齐昵称，积分列右对齐；行高至少 72px                        |
| 排行文字 | 昵称 14/22px，辅助说明 12/18px；长昵称省略并保留完整无障碍描述；积分 18/26px，使用等宽数字     |
| 积分汇总 | 奖杯图标 20px、标题 13px、总分 36/44px、单位 13px；身份与阅读称号使用轻量行内文字              |
| 积分明细 | 来源 14/22px 自然换行；日期及时间 12/18px；积分 18/26px 右对齐；行高至少 68px                  |
| 状态卡片 | 24px 图标、18/26px 标题、14/24px 说明；16px 圆角细边框，按钮至少 44px 高                       |
| 三类状态 | 无记录说明下一步；加载中提示自动更新；失败给出网络提示及“重新加载”，避免将请求失败显示成空榜单 |
| 公共提示 | 全局加载、全局错误和未获证提示沿用同一状态卡片规则；已确认的证书图片及保存分享规则保持既有实现 |

加载或请求失败时暂时收起旧排行榜、积分汇总及明细，防止旧数据与新状态同时出现。重试成功后显示服务返回的数据。离开排行榜或积分页会清理局部状态；并发页面同步共享一次请求，旧页面的迟到失败不会替换当前页面。后台轮询失败也会显示当前记录页的错误，连接恢复后清除。

## 评审与代码

当前预览使用隔离评审存档，画面里的 25 积分和第 5 名均为示例；不会修改玩家进度。浏览器评审入口使用 `revision=records-ui-20261022`，新增场景为 `ranking`、`ranking-loading`、`points`、`points-empty`、`points-loading`、`points-failure`、`certificate-empty`，并保留原有 `ranking-empty`、`ranking-failure`。

- 主要实现：`miniprogram/pages/game/index.js`、`index.wxml`、`records-ui-20261022.wxss`，样式由 `index.wxss` 最后导入。
- 四套同步：`tools/sync-art-refinement-20261022.cjs`，每套 71 个文件逐项哈希相符。AppID、HTTP 连接与身份配置、题库目录及独立入口保留原值。
- 效果拼图：`qa/records-ui-20261022/排行积分与状态规范.jpg`。来自微信模拟器实际截图，右侧状态卡按测量位置裁切。
