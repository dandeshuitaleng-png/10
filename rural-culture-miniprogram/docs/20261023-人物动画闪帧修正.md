# 人物动画结束时闪帧修正

> 阶段记录：本文保留 2026-10-22／23 的设计决策与当时检查结果。当前规则见 [维护索引](MAINTENANCE.md)，代码质量和远端检查见 [本轮修复记录](20261025-代码质量修复与验证.md)。文中的 qa/ 路径为本地历史存档，未随仓库全部上传，不能当作本轮重新验收。

录屏中的异常位于「闯关须知」弹窗。逐帧检查 26.783 秒、1600 帧，确认第 937 帧（15.733 秒）和第 1445 帧（24.200 秒）身体消失一帧，只剩独立的眼部图层。两次异常后，下一帧立即恢复。

## 原因与修正

弹窗的原绘图片和动画 Canvas 交替显示。组件收到 `playing=false` 时，属性观察器先同步清空 Canvas，视图层随后才把原绘图片显示出来，形成一帧交接空档。地图使用同层图片图集，因此此前仅检查地图的采样没有覆盖到这条弹窗渲染路径。

修正在 `components/mascot-actor/index.js`：播放时立即绘制；停止时通过 `wx.nextTick` 等待静态原图的视图更新完成，再清空旧画布。序号校验会取消过期的清空回调，避免连续点击时误清除下一次动作。后台和组件卸载仍立即停止并清空画布。

## 验证范围

- 新增测试使用真实的原绘像素和渲染器，模拟「属性已变化、视图尚未提交」的交接窗口。旧实现可稳定复现身体消失；修正后四季造型均通过。
- 包含快速重播、后台清理、地图滚动等相关动画回归共 28 项通过，页面检查 35 项通过。
- 四套独立工程只同步本次角色组件文件；配置、题库目录和应用入口校验保持一致。
- 四套工程的 JS/JSON/WXML/WXSS 检查通过，最大有效主包 1.929 MiB。
- 四套微信模拟器均已重新编译，确认修正组件加载、手动动作和真实 8 秒自动重播正常执行；停止后渲染器没有待执行动画帧，已保存各主题弹窗截图。具体记录为 `native-handoff-checks.json`。

本说明对应源码和本地微信模拟器检查。修正后尚未获取连续录屏；实体手机长时间运行仍需后续验收，模拟器截图不等于连续录屏。

具体证据位于 `qa/mascot-flash-20261023/`：`recording-analysis.json`、`flash-frame-boundaries.jpg`、`handoff-before.log`、`regression-after.log`、`compile-checks.json` 和 `delivery-sync.json`。
